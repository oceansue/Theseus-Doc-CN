# 应用程序支持与开发

与 Linux 等主流操作系统相比，Theseus 的一个不寻常之处在于：安全的应用程序会被加载到与操作系统其余部分相同的单一地址空间（SAS）中，并以相同的内核特权级运行。下面我们将介绍 Theseus 如何支持这类应用程序，以及如何开发一个新应用。

## 应用 crate 的动态链接与加载

应用程序本质上就是被加载进地址空间的目标文件，与其他任何内核 crate 并无二致。
唯一真正的区别在于：它们必须只使用安全代码（禁止使用 unsafe 代码），
并且必须暴露一个名为 `main` 的**公共（public）**入口函数，如下所示。
如果 `main` 函数不是 `pub` 的，它可能会被编译器优化掉，或无法被应用程序加载代码发现，
从而导致该应用 crate 无法运行。

```rust
pub fn main(args: Vec<String>) -> isize { ... }
```

注意，应用程序级的*库*不需要暴露 `main` 函数；
只有那些打算作为可执行文件运行的应用程序才需要。

如果忘记在应用程序中包含 `main()` 函数，Theseus 中的 crate 管理器仍会成功加载并链接它，但无法运行它，并会抛出一个运行时错误。

## 创建并构建新应用

Theseus 的构建系统会自动构建 `applications/` 目录下的所有 crate，因此你只需把新的应用 crate 放到该目录即可。
存放 crate 文件的目录名**必须与**其 Cargo.toml 中 `name` 字段所指定的 crate 名称**完全相同**。

举例来说，你可以按照如下文件结构创建一个名为 `my_app` 的新应用 crate：

```
applications/
├── my_app
│   ├── Cargo.toml
│   └── src
│       └── lib.rs
├── ...
```

`applications/my_app/src/lib.rs` 文件包含应用代码，其中至少要有一个 `fn main()` 函数体（如上所示）。
`applications/my_app/Cargo.toml` 文件**必须指定与所在目录相同的名称**：

```toml
[package]
name = "my_app"
...
```

构建并运行 Theseus 之后，你可以在 Theseus shell 中输入 `my_app`，即可按预期运行该应用。

## 依赖：如何使用操作系统的功能

目前，应用程序可以通过其 `Cargo.toml` 文件将任意 Theseus 内核 crate 作为直接依赖。这是一个临时的设计选择，用于弥补当前尚无真正的标准库这一空缺。

将来，它会被 `libtheseus` 与 Rust 标准库的组合所取代，届时应用程序*只能*访问 `libtheseus` 重新导出的内核功能，以及 Rust 标准库所提供的功能。这样做有两大好处：

- 应用程序将无法访问那些虽然是公共的、但属于"敏感"的内核函数，除非它们通过 libtheseus 库被显式地开放给应用程序。
- 应用程序不必知道某个具体功能由哪个内核 crate 提供；它们只需依赖 libtheseus 这个单一的 crate，即可访问任何操作系统功能。它们的依赖管理将变得非常简单。
