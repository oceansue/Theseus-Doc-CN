# 软件开发的黄金法则

*你希望别人怎样为你写代码，就怎样为别人写代码。*

这意味着什么？你应当遵循以下原则。

- **良好的抽象。** 使用你的代码的其他开发者，永远不应被迫去钻研代码本身的内部实现，
而应能够仅仅通过结构体/函数的名称和文档，就完全理解如何使用你的代码。
使用直观的命名，并努力设计出一个合理的接口——简单易用，不会用不必要的花招让任何人感到意外。
- **保持整洁。** 编写精心打磨、简洁的代码，具备足以发挥作用的特性，但不臃肿。
遵守代码风格约定，包括恰当的空格、文档注释、命名规范等。
- **防呆的代码。** 仔细思考别人会如何使用你的代码，
并在设计时用心防止他人在使用你的代码时犯错——
理想情况下应在编译期加以阻止，而不是在运行期。
- **错误很重要！** 优雅且彻底地处理错误，
并返回能够清晰描述问题的详细错误信息。*千万不要让任何东西静默地失败！*

下面是一些其他的好实践。

- **准确的元数据。** 除了良好的代码和文档之外，还要确保填写额外的元数据，
例如每个 crate 的 `Cargo.toml` 文件中提供的那些信息：描述、关键词、作者等。
- **不要使用"魔法"数字。** 不要使用没有任何文档或解释说明其存在原因的字面数值。
例如，不要直接在代码里写一个像 4096 这样的值，而应创建一个能准确描述该值语义的 `const`，
例如 `const PAGE_SIZE: usize = 4096;`。
魔法数字极难维护，对未来任何查看你代码的人都没有帮助。
- **尽量减少全局状态。** 尽可能移除静态（全局）状态，并重新思考如何在不使用全局变量的情况下实现同样的数据共享。

## Rust 特有的准则

- **Rust 风格。** 遵循恰当的 Rust 编码风格与命名约定。使用与现有风格一致的正确的空格、缩进和对齐。
让你的代码在视觉上美观宜人，例如等号、加号等运算符前后留空格，逗号之后留空格等。标点符号对可读性很重要！
- **Rust 文档。** *为所有结构体、函数和类型*编写规范的 rustdoc 风格文档。
确保所有文档链接都是正确的，并且文档注释使用了正确的 rustdoc 格式。
函数与结构体定义的上方应使用三斜杠 `///`，C 风格的行内注释（或 `/* */` 这类块注释）使用双斜杠 `//`，
而 crate 顶层文档则使用 `//! `。
使用 Markdown 格式来描述函数参数、返回值，并给出用法示例，与 Rust 官方库的做法保持一致。
- **`Option` 与 `Result`。** 正确地使用 Option 与 Result。不要使用含义被重载的特殊值，
例如用某个整数中的 `0` 表示"没有值"之类的做法。
[这里有一篇很好的资料](https://blog.burntsushi.net/rust-error-handling/)，可以帮助你更好地理解 Rust 中的错误处理。
当某个操作可能失败，但该失败条件不会影响系统其余部分时，应返回 `Option`。
例如，如果你在列表中搜索某个元素，那么 `Option` 就是合适的选择，因为你的 getter 函数的调用者调用它只是为了获取并使用返回值。
当某个操作可能成功也可能失败，调用者需要知道它是否成功，并且可能还需要真正的返回值时，应返回 `Result`，
例如一个返回类型为 void 的初始化函数。
在这种情况下，`Result` 是最佳选择，因为我们要迫使调用者确认初始化函数已经成功，或者在其失败时处理错误。
在 Theseus 中，只要某个函数具有副作用——例如设置一个可能不存在或尚未初始化的参数或值——就必须使用 `Result`。
在这种情况下，必须用一个 result 来表明该函数是否成功。

## Theseus 特有的准则

- **正确且完整地处理 `Result`。** 不要忽略某个 result 的错误；相反，应记录该错误，并在可能的情况下处理它。
如果你无法处理它，就把该错误返回给调用者，让他们尝试处理。**绝对不要压制错误，也不要偷懒地隐藏错误**。
- **绝不使用 unsafe 代码。** 如果你实在无法避免，那么你应当就你的具体情况与 Theseus 的维护者逐一讨论。
在大多数情况下，unsafe 代码并非必需，可以改写为安全代码。

## 为 Theseus 添加新功能

添加新功能最简单的方式，就是复制一个现有的 crate 来创建新 crate，并修改其新 `Cargo.toml` 文件中的细节。
至少，你需要修改 `Cargo.toml` 文件顶部 `[package]` 标题下的 `name` 条目，还需要修改你的新 crate 的依赖。

如果你的新内核 crate 需要初始化，可以在 [`captain::init()` 函数](https://theseus-os.github.io/Theseus/doc/captain/index.html)中调用它，
尽管可能存在更合适的位置，例如用 [`device_manager` 的各个函数](https://theseus-os.github.io/Theseus/doc/device_manager/index.html)来初始化设备驱动。

如果你想为 Theseus 创建一个新的应用程序，请参阅[此处的说明](https://www.theseus-os.com/Theseus/book/app/app.html)。
