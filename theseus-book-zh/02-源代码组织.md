# 源代码组织

Theseus 仓库中的源代码分为三个主要文件夹：

1. kernel/：实现操作系统核心功能的组件
2. applications/：可在 Theseus 中被调用运行的用户应用程序、测试、基准测试等
3. libs/：可在 Theseus 之外独立使用的库组件

### 1. Kernel

`kernel/` 文件夹中的 crate 被视为"第一方"或"特权"组件，必要时可以使用[unsafe 代码](https://doc.rust-lang.org/book/ch19-01-unsafe-rust.html)，例如在操作系统的最底层直接与硬件交互。尽管如此，我们在整个 Theseus 中都竭力避免使用 unsafe 代码。

Kernel crate 不能依赖任何 application crate；否则，该 application crate 会被错误地包含进内核镜像并一同构建。Kernel crate 可以依赖 libs crate。

### 2. Applications

`applications/` 文件夹中的 crate 是不能使用任何 unsafe 代码的用户应用程序。
目前其中主要是专门为 Theseus 开发的简单实用工具和命令行工具，以及用于测试功能或运行性能基准测试的各类小程序。

Application crate 既可以依赖 kernel crate 和 libs crate，也可以依赖其他 application crate，不过并不推荐后一种做法。
关于应用程序的工作原理以及如何开发一个应用程序的更多细节，请参阅[这一节](https://www.theseus-os.com/Theseus/book/app/app.html)。

将来，我们计划限制应用程序只能依赖通过一个专用库（即 `libtheseus`）显式暴露出来的函数和类型，但这属于未来的开发工作。

### 3. Libs

`libs/` 文件夹中的 crate 是独立的项目，*不得*依赖 Theseus 中的任何其他内容，例如 kernel crate 或 application crate。它们旨在被其他软件项目复用，并最终可能会被重构到 Theseus 仓库之外。`libs/` 文件夹中还包含一些我们可能已经 fork 并加以修改、供 Theseus 使用的其他仓库，它们通常以 [git 子模块](https://git-scm.com/book/en/v2/Git-Tools-Submodules)的形式引入。

### 其他文件夹

仓库根目录下的其他文件夹大多是构建/配置工具和脚本。以下是一个简要说明：

- book：包含你正在阅读的这本 Theseus 手册的源代码。
- cfg：包含项目范围的配置 Makefile Config.mk，以及为各种 Theseus 构建指定编译器目标平台的 JSON 文件。
- docker：包含设置一个可用于构建和运行 Theseus 的基础 Docker 镜像所需的脚本和配置文件。
- scripts：包含用于搭建构建环境、测试、调试等的各种杂项脚本。
- tools：包含作为 Theseus 构建过程一部分运行的自定义 Rust 程序。更多信息请参阅 [tools/README](https://github.com/theseus-os/Theseus/tree/theseus_main/tools#readme) 文件。

## 项目工作区

主目录 `kernel` 和 `applications` 中的所有 crate 都被组织进一个单一的顶层*工作区*，这是使用 cargo（Rust 的包管理器和构建工具）把它们一起构建到同一个 `target/` 目录中的一种方式。
这保证了它们可以彼此直接链接，并且它们之间的依赖关系能够由编译器和链接器工具链正确解析。

你可以在根目录的 [Cargo.toml](https://github.com/theseus-os/Theseus/blob/theseus_main/Cargo.toml) 文件中查看该工作区的成员是如何定义的，以及其他所有文件夹是如何被忽略的。这里使用了 cargo 的[虚拟清单](https://doc.rust-lang.org/cargo/reference/workspaces.html)特性。

关于 Theseus [构建过程](https://www.theseus-os.com/Theseus/book/building/building.html)的更多信息请在此阅读。

## 外部依赖

Theseus 确实依赖许多托管在官方 [crates.io](https://crates.io/) 注册表或 GitHub 上的第三方外部 crate。目前所有 crate 都允许使用外部依赖，无论它们是 kernel、application 还是 libs crate。将来，我们可能会限制或禁止应用程序可以使用的 crate 类型，以及它们能否暴露 unsafe 代码或某些底层汇编指令。
