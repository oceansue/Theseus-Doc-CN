# 堆：动态内存分配

堆（heap）用于动态分配比单个页的粒度更小的内存块。

> 注意：你可以向堆请求一次较大的分配，但在 Theseus 中，这样的大分配会由一个单独创建的 `MappedPages` 对象来支撑，其中包含新分配的页和帧，并彼此映射在一起，因此用堆来进行大分配通常效率较低。

在 Theseus 中，堆的首要用途是支持使用 Rust 的 [`alloc`](https://doc.rust-lang.org/alloc/) 类型，例如 `Box`、`Arc`、`Vec` 以及其他动态分配的集合类型。
堆分配器必须实现 Rust 的 [`GlobalAlloc`](https://doc.rust-lang.org/alloc/alloc/trait.GlobalAlloc.html) trait，才能作为这些 `alloc` 类型背后的实际分配器使用。

## 相关 crate 概览

- [`heap`](https://theseus-os.github.io/Theseus/doc/heap/index.html)：默认的堆实现，提供一个静态单例式的固定大小块分配器。
    - 这是在操作系统引导早期第一个被初始化和创建的堆。
    - [`block_allocator`](https://theseus-os.github.io/Theseus/doc/block_allocator/struct.FixedSizeBlockAllocator.html)：底层分配器实现，针对常见的 2 的幂次大小（如 8 字节、32 字节等）的分配做了优化。
        - 对于不常见的分配大小，则使用 [`linked_list_allocator`](https://crates.io/crates/linked_list_allocator) crate 作为后备。
- [`multiple_heaps`](https://theseus-os.github.io/Theseus/doc/multiple_heaps/index.html)：一种更复杂的分配器，实现了多个大小和使用模式各不相同的堆。
    - 每个内部堆实例都基于区域分配器（zone allocator），它是由 [`slabmalloc`](https://crates.io/crates/slabmalloc) crate 中的 slab 分配器修改而来的版本。
    - 未使用的堆空间可以在不同的内部堆实例之间轻松转移，从而实现快速、高效的堆增长。
    - 目前，每个 CPU 核心都会创建一个内部堆，并使用核心 ID 来标识和选择应由哪个堆进行分配。
    - 若想以其他方式使用 multiple_heaps（例如按任务划分堆，或按命名空间划分堆），也非常简单。

Theseus 这种"组合式"堆设计的一个独特之处在于：早期堆、功能完备的堆以及每核心专用堆全部合并为一个单一的堆抽象，可以通过一个全局堆单例来访问。
它起初使用上文所述的简单块分配器；随后，在操作系统引导过程中更多关键系统功能被初始化之后，就会调用 [`switch_to_multiple_heaps()`](https://theseus-os.github.io/Theseus/doc/multiple_heaps/fn.switch_to_multiple_heaps.html) 函数，透明地切换到更复杂的、按核心划分的堆分配器。

Theseus 中堆的另一个独特之处在于：整个系统中的所有实体都使用并共享同一组全局堆。这使得内存分配可以在应用程序、库和内核实体之间无缝流转与传递，而无需借助其他 SAS 操作系统中所使用的低效而复杂的[交换堆（exchange heap）](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/EuroSys2007_SealedProcesses.pdf)。

> 注意：Theseus 的组合式堆设计实现于 Rust 的 `alloc` 类型支持非全局分配器和就地构造（placement constructor）之前。
